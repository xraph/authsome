---
title: Per-Environment Isolation
description: What an environment keeps separate, how the environment is chosen, and how its settings layer over the app's.
---

Users, sessions and organizations carry both an `app_id` and an `env_id`. The same email address can have one account in development and a separate one in production, with different IDs, passwords and sessions.

## How lookups are scoped

The store methods that find a user take the environment explicitly, for example `GetUserByEmail(ctx, appID, envID, email)` on `store.Store`. Sign-up and sign-in resolve the environment before they look anything up:

- Over HTTP, the request has no environment field, so the app's default environment is used. With `WithBootstrap`, that's Development until you call `SetDefaultEnvironment`.
- From Go, set `EnvID` on `account.SignUpRequest` or `account.SignInRequest`. An empty `EnvID` also means the default.

```go
u, sess, err := eng.SignUp(ctx, &account.SignUpRequest{
    AppID:    appID,
    EnvID:    productionEnvID,
    Email:    "alice@example.com",
    Password: "SecureP@ss123",
})
```

Organizations get their environment from the `EnvID` you set when you create them.

## Choosing the environment per request

`middleware.EnvironmentMiddleware` resolves an environment from the `X-Environment-ID` header, then from an API key prefix if you give it a detector, then from the app's default. It stores the environment and its resolved settings on the context (`middleware.EnvIDFrom`, `EnvironmentFrom`, `EnvironmentSettingsFrom`). Neither the standalone API nor the Forge extension installs it, so the sign-up and sign-in handlers don't consult it; add it for your own handlers:

```go
router.Use(middleware.EnvironmentMiddleware(middleware.EnvironmentMiddlewareConfig{
    ResolveEnvironment: func(envID id.EnvironmentID) (*environment.Environment, error) {
        return eng.GetEnvironment(context.Background(), envID)
    },
    ResolveDefault: func(appID id.AppID) (*environment.Environment, error) {
        return eng.GetDefaultEnvironment(context.Background(), appID)
    },
}))
```

It needs the app on the context first (`middleware.AppIDFrom`), which the auth middleware sets for signed-in requests.

## Settings layering

Session settings resolve with the most specific value winning:

1. The environment's settings (`TokenTTLSeconds`, `RefreshTokenTTLSeconds` and the rest on `environment.Settings`)
2. The app's session config (`appsessionconfig.Config`, set with `WithAppSessionConfig` or the admin API)
3. The engine's `Config.Session`

`eng.SessionConfigForApp(ctx, appID, envID)` returns the merged result. The environment type supplies defaults underneath the environment's own settings; see [Environments Overview](/docs/environments/overview).

Other environment settings cover email verification (`SkipEmailVerification`), the password minimum and breached-password check, rate limits, lockout, a webhook URL override and per-provider OAuth client overrides (`OAuthOverrides`).
