title: MongoDB
description: MongoDB backend for teams operating a document-oriented data platform.

The MongoDB store (`store/mongo`) provides a document-oriented backend using Grove ORM with `mongodriver`. It implements `store.Store`, keeps each kind of record in its own collection and creates the indexes during migration.

## Installation

```bash
go get github.com/xraph/authsome
go get github.com/xraph/grove
go get github.com/xraph/grove/drivers/mongodriver
```

## Creating a store

```go
import (
    "log"
    "os"

    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/mongodriver"

    "github.com/xraph/authsome/store/mongo"
)

mdb := mongodriver.New()
if err := mdb.Open(ctx, os.Getenv("MONGODB_URI"),
    mongodriver.WithDatabase("authsome"),
    mongodriver.WithMaxPoolSize(50),
); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(mdb)
if err != nil {
    log.Fatal(err)
}

mgoStore := mongo.New(db)
```

Without `WithDatabase`, the driver takes the database name from the URI. Other options include `WithMinPoolSize`, `WithConnectTimeout`, `WithServerSelectionTimeout` and `WithTimeout`. TLS and Atlas settings go in the URI.

### Connection string format

Standard MongoDB connection strings are supported:

```
mongodb://user:password@localhost:27017/authsome
mongodb+srv://user:password@cluster.mongodb.net/authsome?retryWrites=true&w=majority
mongodb://localhost:27017/authsome?authSource=admin
```

## Wiring into the engine

```go
eng, err := authsome.NewEngine(
    authsome.WithStore(mgoStore),
    authsome.WithDriverName("mongo"),
    authsome.WithDB(db),
    authsome.WithChronicle(chronicleBridge),
    authsome.WithWarden(wardenEngine),
    authsome.WithPlugin(password.New()),
)
if err != nil {
    log.Fatal(err)
}
if err := eng.Start(ctx); err != nil {
    log.Fatal(err)
}
defer eng.Stop(ctx)
```

`WithDB(db)` lets plugins with their own stores (mfa, sso and others) use MongoDB instead of memory. Serve the API the way [Getting Started](/docs/getting-started) does. Most plugins only ship PostgreSQL and SQLite migration groups, so on MongoDB the store's own migrations are what create the collections and indexes.

## Migrations

`eng.Start(ctx)` runs the store's migrations through Grove's orchestrator, creating collections and indexes. There's no schema for the documents themselves.

Migration history is tracked in a `grove_migrations` collection within the same database.

Running migrations manually:

```go
if err := mgoStore.Migrate(ctx); err != nil {
    log.Fatal("migration failed:", err)
}
```

## Collection naming

All Authsome collections use the `authsome_` prefix:

| Collection | Purpose |
|------------|---------|
| `authsome_apps`, `authsome_environments` | Apps and their environments |
| `authsome_users`, `authsome_user_emails` | Users and their addresses |
| `authsome_sessions`, `authsome_revoked_refresh_tokens` | Sessions and refresh-token replay records |
| `authsome_verifications`, `authsome_password_resets` | Verification and reset tokens |
| `authsome_organizations`, `authsome_members`, `authsome_invitations`, `authsome_teams` | Organizations |
| `authsome_devices` | Devices |
| `authsome_webhooks`, `authsome_notifications` | Webhooks and notifications |
| `authsome_api_keys`, `authsome_service_accounts` | API keys and service accounts |
| `authsome_delegations` | Delegations |
| `authsome_form_configs`, `authsome_branding_configs` | Dynamic forms and branding |
| `authsome_app_session_configs` | Per-app session settings |
| `authsome_kv` | Key-value data |

## Indexes

The migration system creates the following indexes automatically:

### Users

| Fields | Type |
|--------|------|
| `app_id, email` | Unique |
| `app_id, username` | Unique, partial (only documents that have a username) |
| `app_id, created_at` | Standard |

### Sessions

| Fields | Type |
|--------|------|
| `token` | Unique |
| `refresh_token` | Unique |
| `user_id, created_at` | Standard |
| `expires_at` | Standard. It isn't a TTL index, so expired sessions stay until something deletes them |

### API Keys

| Fields | Type |
|--------|------|
| `app_id, key_prefix` | Unique |
| `app_id, created_at` and `app_id, user_id, created_at` | Standard |

### Other collections

Verification, reset and invitation tokens have unique indexes on `token`. Organizations and teams are unique on their slug within the parent, and members on `user_id, org_id`.

## BSON serialization

Authsome's MongoDB store serializes all entities as BSON documents. TypeID fields (e.g., `ausr_01j...`) are stored as BSON strings. Timestamps are stored as BSON dates for native MongoDB date queries. Embedded maps (`metadata`, `settings`) are stored as BSON subdocuments.

The BSON field names use snake_case matching Authsome's JSON field names:

```json
{
  "_id": "ausr_01j8x9y7z...",
  "app_id": "aapp_01j...",
  "email": "user@example.com",
  "email_verified": true,
  "created_at": { "$date": "2024-01-15T10:30:00Z" },
  "updated_at": { "$date": "2024-01-15T10:30:00Z" }
}
```

## Lifecycle methods

| Method | Behaviour |
|--------|-----------|
| `Migrate(ctx, extraGroups...)` | Creates collections and indexes through the Grove orchestrator. Idempotent |
| `Ping(ctx)` | Checks connectivity |
| `Close()` | Closes the `*grove.DB` |

## When to use

Use it when your team already runs MongoDB (Atlas or self-hosted) and wants Authsome on the same cluster.

## When not to use

On a new project with no MongoDB already in place, PostgreSQL is simpler to run and gets every plugin's migrations.
