---
title: Memory Store
description: In-memory store for unit tests, integration tests, and local development without a database.
---

The memory store (`store/memory`) is a fully in-memory implementation of `store.Store`. Data lives in Go maps behind a mutex, so it's safe for concurrent use. It needs no configuration and loses everything when the process exits.

## Installation

The memory store is included in the core Authsome module. No additional packages are needed.

```go
import "github.com/xraph/authsome/store/memory"
```

## Creating a store

```go
memStore := memory.New()
```

`memory.New()` returns a ready `*memory.Store`. The zero value isn't usable, so always call `New()`.

## Wiring into the engine

```go
eng, err := authsome.NewEngine(
    authsome.WithStore(memory.New()),
    authsome.WithChronicle(bridge.NewMemoryChronicle()),
    authsome.WithWarden(wardenEngine),
    authsome.WithDisableMigrate(), // nothing to migrate
    authsome.WithPlugin(password.New()),
)
```

`bridge.NewMemoryChronicle()` is an in-memory audit trail that suits tests. [Getting Started](/docs/getting-started) runs a full server on this store.

## Implemented interfaces

The store implements all of `store.Store` (see [Store Backends](/docs/stores/overview)), checked at compile time:

```go
var _ store.Store = (*Store)(nil)
```

## Concurrency safety

Reads take a read lock and writes take the write lock, so tests that sign users in and out from several goroutines are fine.

## Lifecycle methods

| Method | Behaviour |
|--------|-----------|
| `Migrate(ctx, extraGroups...)` | No-op. Always returns `nil`. |
| `Ping(ctx)` | Always returns `nil`. |
| `Close()` | No-op. Always returns `nil`. |

The memory store has no schema to create and no connection to verify, so all lifecycle methods succeed immediately.

## Lookup behaviour

Lookups by email, username or token scan the maps. That's fine for test data, but don't benchmark the auth path against this store.

## Error handling

The memory store returns `store.ErrNotFound` when something doesn't exist, like the other backends:

```go
var ErrNotFound = errors.New("authsome: not found")
```

Check for it with `errors.Is(err, store.ErrNotFound)`.

## Using the memory store in tests

This test passes as written:

```go
package auth_test

import (
    "encoding/json"
    "testing"

    "github.com/stretchr/testify/require"
    "github.com/xraph/warden"
    wmemory "github.com/xraph/warden/store/memory"

    "github.com/xraph/authsome"
    "github.com/xraph/authsome/account"
    "github.com/xraph/authsome/bridge"
    "github.com/xraph/authsome/plugins/password"
    "github.com/xraph/authsome/settings"
    "github.com/xraph/authsome/store/memory"
)

func newTestEngine(t *testing.T) *authsome.Engine {
    t.Helper()
    ctx := t.Context()

    authz, err := warden.NewEngine(warden.WithStore(wmemory.New()))
    require.NoError(t, err)

    eng, err := authsome.NewEngine(
        authsome.WithStore(memory.New()),
        authsome.WithChronicle(bridge.NewMemoryChronicle()),
        authsome.WithWarden(authz),
        authsome.WithDisableMigrate(),
        authsome.WithPlugin(password.New()),
        authsome.WithBootstrap(authsome.WithBootstrapAppName("Test")),
    )
    require.NoError(t, err)
    require.NoError(t, eng.Start(ctx))
    t.Cleanup(func() { _ = eng.Stop(ctx) })

    // Sign-in needs a verified email by default; switch that off for tests.
    require.NoError(t, eng.Settings().Set(ctx, "auth.require_email_verification",
        json.RawMessage(`false`), settings.ScopeGlobal, "", "", "", "test"))

    return eng
}

func TestSignUpAndSignIn(t *testing.T) {
    eng := newTestEngine(t)
    ctx := t.Context()
    appID := eng.PlatformAppID()

    u, sess, err := eng.SignUp(ctx, &account.SignUpRequest{
        AppID:    appID,
        Email:    "alice@example.com",
        Password: "SecureP@ss123",
    })
    require.NoError(t, err)
    require.NotEmpty(t, sess.Token)

    u2, _, err := eng.SignIn(ctx, &account.SignInRequest{
        AppID:    appID,
        Email:    "alice@example.com",
        Password: "SecureP@ss123",
    })
    require.NoError(t, err)
    require.Equal(t, u.ID, u2.ID)
}
```

Sign-in refuses unverified emails by default, so the helper switches `auth.require_email_verification` off. Rate limiting and lockout are on too; a test that signs in many times can replace them with `eng.SetRateLimiter(ratelimit.NewNoopLimiter())` and `eng.SetLockoutTracker(lockout.NewNoopTracker())`.

## Swapping to a production backend

Pass a different store to `authsome.WithStore`, add `WithDriverName`, and drop `WithDisableMigrate()`. See [PostgreSQL](/docs/stores/postgres).

## When to use

Use it for unit and integration tests, CI without a database container, and quick local experiments.

## When not to use

Don't use it in production (a restart loses everything) or with more than one instance (each process has its own data, so a session from one isn't valid on another).
