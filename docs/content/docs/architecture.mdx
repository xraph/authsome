Authsome is organized around a central `Engine` type that orchestrates authentication across a composable set of plugins, store backends, and bridge interfaces. Understanding this structure helps you make informed decisions about which components to use and how to extend the system.

## Engine

The `Engine` is the top-level orchestrator. It holds references to the store, plugin registry, strategy registry, hook bus, and all bridge interfaces. All authentication logic flows through the engine.

```go
import "github.com/xraph/authsome"

eng, err := authsome.NewEngine(
    authsome.WithStore(myStore),
    authsome.WithPlugin(passwordPlugin),
    authsome.WithWarden(wardenEngine),    // required: authorization
    authsome.WithChronicle(chronicle),    // required: audit trail
    authsome.WithMailer(mailer),          // optional: transactional email
)
```

The engine is constructed with `authsome.NewEngine(opts...)` and activated with `eng.Start(ctx)`. It exposes the full service API as methods on `*Engine`.

## Store abstraction

All persistence goes through the `store.Store` composite interface. Swap the backend at construction time with no other changes.

```go
// Development: no external dependencies
st := memory.New()

// Production: PostgreSQL, on a Grove database opened with pgdriver
st := postgres.New(groveDB)

// SQLite (sqlitedriver) or MongoDB (mongodriver) work the same way
st := sqlite.New(groveDB)
st := mongo.New(groveDB)
```

Each SQL or Mongo store takes a `*grove.DB`; [Store Backends](/docs/stores/overview) shows how to open one and lists the domain stores that `store.Store` is made of (users, sessions, accounts, apps, organizations, devices, webhooks, notifications, API keys, environments, form and branding configs, per-app session and client configs, settings, service accounts, principals, KV, retention and paging).

## Plugin system

Plugins are the primary extension point. Each plugin implements the `plugin.Plugin` base interface and any combination of optional lifecycle interfaces.

```go
// Base interface: all plugins must implement this.
type Plugin interface {
    Name() string
}

// Optional lifecycle interfaces a plugin may implement:
type OnInit interface {
    OnInit(ctx context.Context, e PluginEngine) error
}
type RouteProvider interface {
    RegisterRoutes(r forge.Router, e PluginEngine)
}
type MigrationProvider interface {
    Migrations(driver string) []migrate.Migration
}
type BeforeSignUp interface {
    OnBeforeSignUp(ctx context.Context, req *account.SignUpRequest) error
}
type AfterSignUp interface {
    OnAfterSignUp(ctx context.Context, u *user.User, sess *session.Session)
}
type BeforeSignIn interface {
    OnBeforeSignIn(ctx context.Context, req *account.SignInRequest) error
}
type AfterSignIn interface {
    OnAfterSignIn(ctx context.Context, u *user.User, sess *session.Session)
}
type AuthMethodContributor interface {
    AuthMethods() []AuthMethod
}
```

The engine's plugin registry discovers capabilities at registration time using type assertions.

## Hook bus

The hook bus emits structured events for every significant operation. Listeners can react to events for metrics, audit, downstream notifications, or custom business logic.

```go
import "github.com/xraph/authsome/hook"

// Subscribe to sign-up events.
eng.Hooks().Subscribe(hook.ActionSignUp, func(ctx context.Context, event *hook.Event) {
    log.Printf("new signup: user=%s app=%s", event.ResourceID, event.Tenant)
})
```

## Strategy registry

Authentication strategies are registered with a priority, and the registry tries them in priority order.

```go
import "github.com/xraph/authsome/strategy"

// Plugins register their strategies themselves. To add your own:
authsome.WithStrategy(myStrategy, 5)

// or, on a built engine:
eng.Strategies().Register(myStrategy, 5)
```

Lower priority values are evaluated first (priority 1 runs before priority 10). This allows you to insert custom strategies that intercept before built-in ones.

## Bridges

Bridges are the interfaces Authsome uses to reach other systems. Chronicle and Warden are required: `NewEngine` returns an error without them. The rest are optional, and when one isn't configured Authsome uses a no-op and skips that work.

| Bridge | Interface | Used for |
|--------|-----------|----------|
| `Chronicle` | `bridge.Chronicle` | Audit trail: records every auth event with severity and outcome |
| `Relay` | `bridge.EventRelay` | Webhook delivery: forwards hook events to registered endpoints |
| `Mailer` | `bridge.Mailer` | Transactional email for magic links, verifications, password resets |
| `SMSSender` | `bridge.SMSSender` | SMS delivery for phone OTP and MFA SMS codes |
| `Herald` | `bridge.Herald` | Unified multi-channel notification system (replaces Mailer + SMS) |
| `Warden` | `*warden.Engine` (`WithWarden`), or a `bridge.Authorizer` (`WithAuthorizer`) | Authorization for RBAC/ReBAC/ABAC policy evaluation |
| `Keysmith` | `bridge.KeyManager` | API key management with rotation, scopes, and usage tracking |
| `Vault` | `bridge.Vault` | Secrets management and feature flag access |
| `Dispatch` | `bridge.Dispatcher` | Background job queue for async tasks |
| `Ledger` | `bridge.Ledger` | Billing/metering integration |
| `Metrics` | `bridge.MetricsCollector` | Hook-bus events and operational counters for a collector of your own. authsome's own metric families go through `WithMetricsSink`; see [Observability](/docs/concepts/observability) |

### Bridge adapters

Each bridge ships with one or more pre-built adapters:

```go
import (
    "github.com/xraph/authsome/bridge/chronicleadapter"
    "github.com/xraph/authsome/bridge/maileradapter"
    "github.com/xraph/authsome/bridge/smsadapter"
    "github.com/xraph/authsome/bridge/relayadapter"
)

// Chronicle: wrap a Chronicle engine
authsome.WithChronicle(chronicleadapter.New(chronicleEngine))

// Mailer: SMTP or Resend
authsome.WithMailer(maileradapter.NewSMTPMailer("smtp.example.com", "587", user, pass, "noreply@example.com"))
authsome.WithMailer(maileradapter.NewResendMailer(resendAPIKey, "noreply@example.com"))

// SMS: Twilio
authsome.WithSMSSender(smsadapter.NewTwilioSender(accountSID, authToken, "+15550001111"))

// Relay: wrap a Relay engine
authsome.WithEventRelay(relayadapter.New(relayEngine))
```

## API layer and middleware

The HTTP API is a set of Forge routes. In a Forge app, register the extension and it mounts them for you:

```go
import authsomeext "github.com/xraph/authsome/extension"

app.RegisterExtension(authsomeext.New(
    authsomeext.WithPlugin(password.New()),
    authsomeext.WithPlugin(social.New(socialCfg)),
))
```

Without the extension, mount the API on a Forge router yourself, with the auth middleware in front:

```go
router := forge.NewRouter()
router.Use(middleware.AuthMiddleware(eng.ResolveSessionByToken, eng.ResolveUser, nil))
if err := api.New(eng).RegisterRoutes(router); err != nil {
    log.Fatal(err)
}
for _, rp := range eng.Plugins().RouteProviders() { // plugin routes
    if err := rp.RegisterRoutes(router); err != nil {
        log.Fatal(err)
    }
}
http.ListenAndServe(":8080", router.Handler())
```

The `middleware` package also has guards for your own routes, all `forge.Middleware`:

```go
// Reject requests without an authenticated user.
router.GET("/api/me", handler, forge.WithMiddleware(middleware.RequireAuth()))

// Require a permission. The engine implements PermissionChecker through Warden.
router.GET("/api/admin/users", adminHandler,
    forge.WithMiddleware(middleware.RequirePermission(eng, "read", "users")))
```

`middleware.RateLimit(limiter, cfg)`, `RequireScope`, `RequireAnyRole`, `CSRF` and `SecurityHeaders` are there too.

## Token formats

Access tokens are opaque 64-character hex strings by default. Switch to signed JWTs per app for use cases that require client-side validation or OIDC compatibility.

```go
import "github.com/xraph/authsome/tokenformat"

// JWT format with an RS256 signing key (jwt is github.com/golang-jwt/jwt/v5).
jwtFmt, err := tokenformat.NewJWT(tokenformat.JWTConfig{
    SigningMethod: jwt.SigningMethodRS256,
    SigningKey:    rsaPrivateKey,
    VerifyKey:     &rsaPrivateKey.PublicKey,
    KeyID:         "key-1",
    Issuer:        "https://auth.myapp.com",
    Audience:      "https://api.myapp.com",
})

// Use JWTs for one app.
authsome.WithJWTFormat(appID.String(), jwtFmt)
```

When JWT is configured for an app, all sessions created for that app receive a signed JWT as the access token. The refresh token remains opaque.
