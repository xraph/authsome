This guide installs Authsome, builds an engine with password sign-in, serves its API locally and walks through sign-up with `curl`. Everything runs in memory, so you don't need a database.

## Prerequisites

- Go 1.26 or later
- A Go module (`go mod init your/module`)
- `curl` and `openssl`

## Install

Authsome records every security event to [Chronicle](https://github.com/xraph/chronicle) and checks permissions with [Warden](https://github.com/xraph/warden). The engine refuses to start without both, so install them too:

```bash
go get github.com/xraph/authsome@latest github.com/xraph/chronicle@latest github.com/xraph/warden@latest
```

The core engine, every plugin and the stores (`store/memory`, `store/postgres`, `store/sqlite`, `store/mongo`) are packages in that one module.

## Step 1: Create the engine

Save this as `main.go`:

```go
package main

import (
    "context"
    "log"
    "net/http"

    "github.com/xraph/chronicle"
    chstore "github.com/xraph/chronicle/store"
    chmemory "github.com/xraph/chronicle/store/memory"
    "github.com/xraph/forge"
    "github.com/xraph/warden"
    wmemory "github.com/xraph/warden/store/memory"

    "github.com/xraph/authsome"
    "github.com/xraph/authsome/api"
    "github.com/xraph/authsome/bridge/chronicleadapter"
    "github.com/xraph/authsome/middleware"
    "github.com/xraph/authsome/plugins/password"
    "github.com/xraph/authsome/store/memory"
)

func main() {
    ctx := context.Background()

    // Authsome records every security event to Chronicle and checks
    // permissions with Warden, so both are required.
    trail, err := chronicle.New(chronicle.WithStore(chstore.NewAdapter(chmemory.New())))
    if err != nil {
        log.Fatal(err)
    }
    authz, err := warden.NewEngine(warden.WithStore(wmemory.New()))
    if err != nil {
        log.Fatal(err)
    }

    engine, err := authsome.NewEngine(
        authsome.WithStore(memory.New()),
        authsome.WithChronicle(chronicleadapter.New(trail)),
        authsome.WithWarden(authz),
        authsome.WithDisableMigrate(), // the memory store has nothing to migrate
        authsome.WithPlugin(password.New()),
        authsome.WithBootstrap(authsome.WithBootstrapAppName("Acme")),
    )
    if err != nil {
        log.Fatal(err)
    }
```

`password.New()` registers the password strategy. The account routes (`/signup`, `/signin`, `/forgot-password` and so on) come from the core API.

`WithBootstrap` creates a platform app with its default environments and roles when the engine starts, which gives you an app ID to sign up against.

## Step 2: Start the engine

`Start` runs migrations (unless disabled), seeds the bootstrap app and calls `OnInit` on every plugin. Call `Stop` on shutdown.

```go
    if err := engine.Start(ctx); err != nil {
        log.Fatal(err)
    }
    defer engine.Stop(ctx)
```

## Step 3: Serve the API

The HTTP API is a set of Forge routes. Mount them on a Forge router with the auth middleware in front:

```go
    router := forge.NewRouter()
    router.Use(middleware.AuthMiddleware(engine.ResolveSessionByToken, engine.ResolveUser, nil))
    if err := api.New(engine).RegisterRoutes(router); err != nil {
        log.Fatal(err)
    }
    // Plugins mount their own routes (/v1/orgs, /v1/mfa, /v1/social and so on).
    for _, rp := range engine.Plugins().RouteProviders() {
        if err := rp.RegisterRoutes(router); err != nil {
            log.Fatal(err)
        }
    }

    log.Printf("listening on :8080, app_id=%s", engine.PlatformAppID())
    log.Fatal(http.ListenAndServe(":8080", router.Handler()))
}
```

`api.New(engine).RegisterRoutes` mounts the core routes. Plugins with HTTP endpoints implement `plugin.RouteProvider`, and the loop mounts theirs; the password plugin has none of its own, but magic links, MFA, social login and organizations do. The Forge extension does both for you.

The core routes live under `/v1`:

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/signup` | Create an account and return a session |
| `POST` | `/v1/signin` | Sign in with email and password |
| `POST` | `/v1/signout` | Revoke the current session |
| `POST` | `/v1/refresh` | Exchange a refresh token for new tokens |
| `GET` | `/v1/me` | The signed-in user |
| `PATCH` | `/v1/me` | Update the signed-in user |
| `POST` | `/v1/verify-email` | Confirm an email address |
| `POST` | `/v1/forgot-password` | Request a password reset email |
| `POST` | `/v1/reset-password` | Confirm a reset with its token and a new password |
| `POST` | `/v1/change-password` | Change the password (needs the current one) |

The OpenAPI spec for everything you've mounted is at `/.well-known/authsome/openapi`.

## Step 4: Run it

Authsome encrypts the tokens it stores, so it needs a key. Give it 64 hex characters:

```bash
go mod tidy
export AUTHSOME_TOKEN_ENCRYPTION_KEY=$(openssl rand -hex 32)
go run .
# listening on :8080, app_id=aapp_...
```

You can also pass an encryptor with `authsome.WithTokenEncryptor`, or set `AUTHSOME_TOKEN_ENCRYPTION_KEYS` to `kid:hex` pairs when you rotate keys.

## Step 5: Test with curl

### Sign up

Put the `app_id` from the log line in the body:

```bash
curl -s -X POST http://localhost:8080/v1/signup \
  -H "Content-Type: application/json" \
  -d '{"app_id":"aapp_...","email":"alice@example.com","password":"SecureP@ss123"}'
```

Response:

```json
{
  "session_token": "0d6283f1...",
  "refresh_token": "ebad821f...",
  "expires_at": "2026-10-14T18:29:39Z",
  "user": {
    "id": "ausr_01m4...",
    "app_id": "aapp_01m4...",
    "env_id": "aenv_01m4...",
    "email": "alice@example.com",
    "email_verified": false
  }
}
```

Browser and mobile clients usually send an `X-Publishable-Key` header instead of the app ID.

### Call /me

```bash
curl -s http://localhost:8080/v1/me \
  -H "Authorization: Bearer <session_token>"
```

### Sign in

`/v1/signin` refuses an account whose email isn't verified, because the `auth.require_email_verification` setting is on by default:

```json
{"code":403,"error":"please verify your email address before signing in","type":"email_not_verified"}
```

Sign-up issues a 6-digit code for this, but Authsome doesn't send it by itself; the `notification` plugin delivers it through a Herald bridge. For local work, either switch the setting off:

```go
// after engine.Start; needs encoding/json and github.com/xraph/authsome/settings
_ = engine.Settings().Set(ctx, "auth.require_email_verification",
    json.RawMessage(`false`), settings.ScopeGlobal, "", "", "", "local-dev")
```

or take the code from `engine.SendEmailVerification(ctx, user)` and post `{"email": "...", "code": "..."}` to `/v1/verify-email`. After that, sign-in returns the same shape as sign-up.

### Refresh tokens

```bash
curl -s -X POST http://localhost:8080/v1/refresh \
  -H "Content-Type: application/json" \
  -d '{"refresh_token":"<refresh_token>"}'
```

You get a new session token and, with refresh rotation on (the default), a new refresh token. The old one stops working.

## Step 6: Add more plugins

Every sign-in method beyond the core is a plugin. Add it next to `password.New()`.

### Magic links

```go
import "github.com/xraph/authsome/plugins/magiclink"

authsome.WithPlugin(magiclink.New(magiclink.Config{
    // The plugin only sends through this Mailer; it doesn't use the
    // engine's mailer bridge. Without one, no email goes out.
    Mailer: magiclink.MailerFunc(func(ctx context.Context, email, token string) error {
        return sendLoginEmail(ctx, email, "https://myapp.com/magic?token="+token)
    }),
})),
```

The client posts the address to `/v1/magic-link/send` and the token to `/v1/magic-link/verify`, which returns a session.

### Google and GitHub sign-in

```go
import "github.com/xraph/authsome/plugins/social"

authsome.WithPlugin(social.New(social.Config{
    Providers: []social.Provider{
        social.NewGoogleProvider(social.ProviderConfig{
            ClientID:     os.Getenv("GOOGLE_CLIENT_ID"),
            ClientSecret: os.Getenv("GOOGLE_CLIENT_SECRET"),
            RedirectURL:  "https://myapp.com/v1/social/google/callback",
        }),
        social.NewGitHubProvider(social.ProviderConfig{
            ClientID:     os.Getenv("GITHUB_CLIENT_ID"),
            ClientSecret: os.Getenv("GITHUB_CLIENT_SECRET"),
            RedirectURL:  "https://myapp.com/v1/social/github/callback",
        }),
    },
})),
```

### TOTP-based MFA

```go
import "github.com/xraph/authsome/plugins/mfa"

authsome.WithPlugin(mfa.New(mfa.Config{
    Issuer: "MyApp",
})),
```

## Step 7: Switch to PostgreSQL

The stores take a [Grove](https://github.com/xraph/grove) database. Open one and pass it to `postgres.New`:

```go
import (
    "github.com/xraph/grove"
    "github.com/xraph/grove/drivers/pgdriver"

    "github.com/xraph/authsome/store/postgres"
)

pg := pgdriver.New()
if err := pg.Open(ctx, "postgres://user:pass@localhost:5432/myapp_auth?sslmode=disable"); err != nil {
    log.Fatal(err)
}
db, err := grove.Open(pg)
if err != nil {
    log.Fatal(err)
}

engine, err := authsome.NewEngine(
    authsome.WithStore(postgres.New(db)),
    authsome.WithDriverName("pg"),
    authsome.WithDB(db),
    // ... Chronicle, Warden, plugins and bootstrap as before,
    // without WithDisableMigrate
)
```

`WithDriverName("pg")` tells plugins which migrations to hand over, and `WithDB(db)` gives them the database. Without `WithDB`, plugins that keep their own data (mfa, social, sso, oauth2provider, scim and others) fall back to in-memory stores, so their enrollments and links vanish on restart. Without `WithDriverName`, the tables only plugins create (SSO identities, consents, the OAuth2 provider's tables and others) never get made. The Forge extension sets both for you.

`Start` applies pending migrations for the core and every registered plugin. To migrate in a separate deployment step instead, build the engine without `WithDisableMigrate()` in that step and call `engine.EnsureMigrated(ctx)`, then pass `WithDisableMigrate()` to the servers. `EnsureMigrated` does nothing on an engine with migrations disabled.
