---
title: Mailer Bridge
description: Transactional email delivery for verification, password resets, magic links, and invitations.
---

The Mailer bridge sends Authsome's transactional email: address verification, password reset links, magic links and organization invitations. You provide the mailer; Authsome writes the messages.

For several channels (email, SMS, push) or template management, use the [Herald bridge](/docs/bridges/herald). When Herald is configured it takes over from the Mailer and SMS bridges.

## Interface

The `bridge.Mailer` interface is defined in `github.com/xraph/authsome/bridge`:

```go
type Mailer interface {
    SendEmail(ctx context.Context, msg *EmailMessage) error
}

type EmailMessage struct {
    To      []string `json:"to"`
    From    string   `json:"from,omitempty"` // Falls back to configured default sender
    Subject string   `json:"subject"`
    HTML    string   `json:"html,omitempty"`
    Text    string   `json:"text,omitempty"` // Plain-text fallback
}
```

## Setup with the Resend adapter

`bridge/maileradapter` ships two adapters, Resend and SMTP.

```go
import (
    "os"

    "github.com/xraph/authsome"
    "github.com/xraph/authsome/bridge/maileradapter"
)

eng, err := authsome.NewEngine(
    // plus WithChronicle and WithWarden, which every engine needs (see Getting Started)
    authsome.WithStore(pgStore),
    authsome.WithPlugin(password.New()),
    authsome.WithMailer(maileradapter.NewResendMailer(
        os.Getenv("RESEND_API_KEY"),
        "My App <noreply@myapp.com>",
    )),
)
```

`NewResendMailer(apiKey, fromAddr, opts...)` also takes `WithResendHTTPClient` and `WithResendBaseURL`.

## Setup with the SMTP adapter

```go
authsome.WithMailer(maileradapter.NewSMTPMailer(
    "smtp.example.com",
    "587", // the port is a string
    os.Getenv("SMTP_USERNAME"),
    os.Getenv("SMTP_PASSWORD"),
    "noreply@myapp.com",
    maileradapter.WithSMTPTLS(true),
)),
```

There's no SendGrid adapter. For SendGrid, Postmark or anything else, implement `bridge.Mailer` yourself, as below.

## Custom implementation

Implement `bridge.Mailer` directly for any email provider:

```go
type PostmarkMailer struct {
    client *postmark.Client
    from   string
}

func (m *PostmarkMailer) SendEmail(ctx context.Context, msg *bridge.EmailMessage) error {
    _, err := m.client.SendEmail(postmark.Email{
        From:     m.from,
        To:       strings.Join(msg.To, ","),
        Subject:  msg.Subject,
        HTMLBody: msg.HTML,
        TextBody: msg.Text,
    })
    return err
}

eng, err := authsome.NewEngine(
    // plus WithChronicle and WithWarden, which every engine needs (see Getting Started)
    authsome.WithStore(pgStore),
    authsome.WithMailer(&PostmarkMailer{
        client: postmark.NewClient(os.Getenv("POSTMARK_TOKEN"), ""),
        from:   "noreply@myapp.com",
    }),
)
```

## What sends through the mailer

The core engine sends no email itself. The mailer bridge is used by:

| Sender | Emails |
|--------|--------|
| `email` plugin | A welcome email after sign-up, and a "verify your email" message when a user is created. That message links to `{BaseURL}/verify-email` but doesn't include the verification code |
| Your own code | Anything you send with `eng.Mailer().SendEmail(...)` |

Other mail goes elsewhere. Verification codes and password resets are delivered by the `notification` plugin through a [Herald bridge](/docs/bridges/herald). Magic links go through `magiclink.Config.Mailer`, which is a different interface.

## Standalone development stub

During development, `bridge.NewNoopMailer(logger)` logs each email at debug level instead of sending it. It takes a go-utils `log.Logger`:

```go
import (
    "github.com/xraph/go-utils/log"

    "github.com/xraph/authsome/bridge"
)

authsome.WithMailer(bridge.NewNoopMailer(log.NewDevelopmentLogger())),
```

Or run Mailpit and point the SMTP adapter at `localhost:1025`, as the [Full Example](/docs/guides/full-example) does.

<Callout type="info">
Without a mailer, the `email` plugin sends nothing and logs nothing. Verification codes and password resets need the `notification` plugin with Herald regardless of the mailer.
</Callout>
