---
title: Metrics Bridge
description: "Hand authsome's hook-bus events and operational counters to a metrics collector of your own."
---

The Metrics bridge gives you authsome's raw signals: every event on the hook bus, and a handful of operational counters. You wire it to whatever you already run.

In a Forge app you probably want something else. The extension passes the app's registry to `WithMetricsSink`, which records authsome's own metric families (sign-in attempts, MFA checks, refreshes, provider latency and more) with bounded labels and needs no code from you. [Observability](/docs/concepts/observability) lists them. Use this bridge when you embed the engine and want the signals in a backend of your own.

## Interface

`bridge.MetricsCollector` lives in `github.com/xraph/authsome/bridge`:

```go
type MetricsCollector interface {
    RecordEvent(action, resource, outcome, tenant string, duration time.Duration)
    IncrementGauge(name, tenant string, delta int)
    IncrementCounter(name, tenant string)
}
```

Register yours with `authsome.WithMetrics(collector)`.

### RecordEvent

The engine calls it once for every hook-bus event, after the audit trail has seen it.

| Parameter | Description |
|-----------|-------------|
| `action` | The event's action, a `hook.Action*` constant such as `auth.signin` or `session.revoke` |
| `resource` | The entity type, such as `session`, `user` or `mfa` |
| `outcome` | `success` or `failure` |
| `tenant` | The app ID the event belongs to |
| `duration` | Always zero today. The engine doesn't time bus events. |

Earlier releases also sent one `http.request` event per HTTP request, from `middleware.Metrics`. That middleware is gone: forge measures every route itself, by route template, and the old event labelled by raw path, which put session IDs and secrets into labels.

### IncrementCounter

The engine calls it for these operational signals:

| Name | When |
|------|------|
| `audit.record.failed` | Chronicle refused an audit record |
| `auth.lockout` | A sign-in was refused because the account is locked |
| `refresh.replay_detected` | A rotated refresh token came back for the first time |
| `control.degraded` | A security control couldn't run and let the request through |
| `identifier_limit.rejected` | The per-identifier limiter refused a request |
| `ratelimit.rejected` | A route limiter refused a request |
| `ratelimit.error` | A limiter couldn't answer |

### IncrementGauge

Part of the interface, but nothing in authsome calls it.

## Don't label by tenant

The `tenant` argument is an app ID. A deployment can hold any number of apps, so a label built from it grows without bound, and a metrics backend pays for every series. Ignore it, as the adapter below does, unless you know your app count stays small.

## The bundled adapter

`bridge/metricsadapter` implements the interface over any go-utils metrics registry, Forge's included:

```go
eng, err := authsome.NewEngine(
    // plus WithStore, WithChronicle and WithWarden, which every engine needs
    authsome.WithMetrics(metricsadapter.New(registry)),
)
```

It records `authsome_events_total{action,resource,outcome}`, a counter per `IncrementCounter` name with a `_total` suffix (`auth.lockout` becomes `authsome_auth_lockout_total`), and a gauge per `IncrementGauge` name. It ignores the tenant, gives every series in a family the same label keys, and folds a value that isn't shaped like a constant into `other`.

Don't use it alongside `WithMetricsSink` on the same registry: the sink records `authsome_events_total` too, and the two would count every event twice.

## A Prometheus collector of your own

```go
type promCollector struct {
    events   *prometheus.CounterVec
    counters *prometheus.CounterVec
}

func newPromCollector(reg prometheus.Registerer) *promCollector {
    return &promCollector{
        events: promauto.With(reg).NewCounterVec(prometheus.CounterOpts{
            Name: "authsome_events_total",
            Help: "Hook-bus events by action, resource and outcome.",
        }, []string{"action", "resource", "outcome"}),
        counters: promauto.With(reg).NewCounterVec(prometheus.CounterOpts{
            Name: "authsome_signals_total",
            Help: "authsome's operational signals by name.",
        }, []string{"name"}),
    }
}

func (c *promCollector) RecordEvent(action, resource, outcome, _ string, _ time.Duration) {
    c.events.WithLabelValues(action, resource, outcome).Inc()
}

func (c *promCollector) IncrementCounter(name, _ string) {
    c.counters.WithLabelValues(name).Inc()
}

func (c *promCollector) IncrementGauge(string, string, int) {}
```

## Without a collector

Nothing changes. The engine checks for a nil collector before each call, so leaving it out costs nothing.
