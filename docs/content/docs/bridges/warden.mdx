---
title: Warden Bridge
description: The required authorization engine. Authsome's roles, permissions and permission checks all go through Warden.
---

Warden is Authsome's authorization engine, and it's required: `NewEngine` returns an error without `WithWarden`. Roles, permissions, role assignments and permission checks (`eng.HasPermission`, `middleware.RequirePermission`) all go through Warden's RBAC, ReBAC and ABAC evaluation.

## Interface

The `bridge.Authorizer` interface is defined in `github.com/xraph/authsome/bridge`:

```go
type Authorizer interface {
    Check(ctx context.Context, req *AuthzRequest) (*AuthzResult, error)
}

type AuthzRequest struct {
    Subject  string `json:"subject"`   // User ID
    Action   string `json:"action"`    // e.g. "read", "write", "delete"
    Resource string `json:"resource"`  // e.g. "document", "api:v1/users"
    Tenant   string `json:"tenant,omitempty"`
}

type AuthzResult struct {
    Allowed bool   `json:"allowed"`
    Reason  string `json:"reason,omitempty"`
}
```

## Setup

```go
import (
    "github.com/xraph/warden"
    wmemory "github.com/xraph/warden/store/memory"

    "github.com/xraph/authsome"
)

wardenEng, err := warden.NewEngine(
    warden.WithStore(wmemory.New()), // or one of Warden's persistent stores
)
if err != nil {
    log.Fatal(err)
}

eng, err := authsome.NewEngine(
    authsome.WithStore(pgStore),
    authsome.WithChronicle(chronicleBridge),
    authsome.WithWarden(wardenEng),
)
```

`WithWarden` also sets the `bridge.Authorizer` to `wardenadapter.New(wardenEng)`. Other Warden options include `WithCache`, `WithEvaluator`, `WithLogger` and `WithConfig`; see Warden's documentation.

## A custom Authorizer

`WithAuthorizer` replaces the `bridge.Authorizer` that `WithWarden` set, for code paths that check through the bridge. It doesn't replace Warden: you still pass `WithWarden`, because role and permission storage live there.

```go
authsome.WithWarden(wardenEng),
authsome.WithAuthorizer(myAuthorizer), // implements bridge.Authorizer
```

## How Authsome uses Warden

- `eng.HasPermission(ctx, userID, action, resource)` and the `middleware.RequirePermission` guard check permissions in Warden.
- Role and permission management on the engine (`CreateRole`, `AssignUserRole`, `AddPermission` and the rest) writes to Warden's store.
- `WithBootstrap` seeds the default roles into Warden when the engine starts.

Policies themselves are written in Warden. See Warden's documentation for its policy language and stores.
