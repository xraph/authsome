---
title: SMS Bridge
description: SMS delivery for OTP codes, MFA verification, and phone number verification.
---

The SMS bridge sends Authsome's text messages: phone sign-in codes from the `phone` plugin and SMS codes for MFA. You provide the sender; Authsome writes the messages.

For several channels or template management, use the [Herald bridge](/docs/bridges/herald). When Herald is configured it takes over from the Mailer and SMS bridges.

## Interface

The `bridge.SMSSender` interface is defined in `github.com/xraph/authsome/bridge`:

```go
type SMSSender interface {
    SendSMS(ctx context.Context, msg *SMSMessage) error
}

type SMSMessage struct {
    To   string `json:"to"`   // E.164 format, e.g. "+14155551234"
    Body string `json:"body"` // Plain text message body
}
```

## Setup with the Twilio adapter

`bridge/smsadapter` ships one adapter, for Twilio:

```go
import (
    "os"

    "github.com/xraph/authsome"
    "github.com/xraph/authsome/bridge/smsadapter"
    "github.com/xraph/authsome/plugins/mfa"
    "github.com/xraph/authsome/plugins/phone"
)

eng, err := authsome.NewEngine(
    // plus WithChronicle and WithWarden, which every engine needs (see Getting Started)
    authsome.WithStore(pgStore),
    authsome.WithPlugin(mfa.New(mfa.Config{Issuer: "My App"})),
    authsome.WithPlugin(phone.New()),
    authsome.WithSMSSender(smsadapter.NewTwilioSender(
        os.Getenv("TWILIO_ACCOUNT_SID"),
        os.Getenv("TWILIO_AUTH_TOKEN"),
        os.Getenv("TWILIO_FROM_NUMBER"), // E.164, e.g. "+12015551234"
    )),
)
```

The phone plugin uses the engine's SMS sender unless you give it one in `phone.Config{SMSSender: ...}`. There's no AWS SNS adapter; implement `bridge.SMSSender` for SNS or any other provider.

## Custom implementation

Implement `bridge.SMSSender` directly for any SMS provider:

```go
type VonageSMSSender struct {
    client  vonage.SMSClient
    from    string
}

func (s *VonageSMSSender) SendSMS(ctx context.Context, msg *bridge.SMSMessage) error {
    _, _, err := s.client.Send(s.from, msg.To, msg.Body, nil)
    return err
}

eng, err := authsome.NewEngine(
    // plus WithChronicle and WithWarden, which every engine needs (see Getting Started)
    authsome.WithStore(pgStore),
    authsome.WithSMSSender(&VonageSMSSender{
        client: vonage.NewSMSClient(vonage.CreateAuthClient(
            os.Getenv("VONAGE_API_KEY"),
            os.Getenv("VONAGE_API_SECRET"),
        )),
        from: os.Getenv("VONAGE_FROM"),
    }),
)
```

## SMS messages sent by Authsome

| Trigger | Message |
|---------|---------|
| MFA SMS code | A six-digit code, valid for 5 minutes |
| Phone sign-in | A one-time code from the `phone` plugin, valid for its `CodeTTL` |

For your own wording, use the [Herald bridge](/docs/bridges/herald).

## Phone number format

Send phone numbers in E.164 format: `+`, the country code and the subscriber number, with no spaces or hyphens.

Examples:
- US: `+14155551234`
- UK: `+441234567890`
- Germany: `+4915123456789`

## Standalone development stub

`bridge.NewNoopSMSSender()` returns `bridge.ErrSMSNotAvailable` from every call. To capture codes in tests, write a small sender:

```go
type TestSMSSender struct {
    mu       sync.Mutex
    Messages []*bridge.SMSMessage
}

func (s *TestSMSSender) SendSMS(_ context.Context, msg *bridge.SMSMessage) error {
    s.mu.Lock()
    defer s.mu.Unlock()
    s.Messages = append(s.Messages, msg)
    return nil
}

authsome.WithSMSSender(&TestSMSSender{}),
```

<Callout type="info">
When no SMS bridge is configured, Authsome's phone plugin and SMS-based MFA return errors when SMS delivery is attempted. Always configure an SMS sender in any environment where phone-based auth methods are enabled.
</Callout>
