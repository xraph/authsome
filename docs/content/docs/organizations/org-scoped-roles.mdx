---
title: Org-Scoped Roles
description: What org scoping means for roles today, and how roles and permissions actually work.
---

Authsome has two kinds of role. Organization member roles (`owner`, `admin`, `member`) come from the organization plugin and gate its own routes; see [Members](/docs/organizations/members). App roles live in Warden and back `eng.HasPermission` and `middleware.RequirePermission`.

<Callout type="warn">
App roles aren't scoped to an organization yet. `rbac.UserRole` has an `OrgID` field, and `POST /v1/roles/:roleId/assign` accepts `org_id`, but the Warden-backed role store drops it: the assignment is stored app-wide, and permission checks run against the app as the Warden tenant. A role assigned "in" one organization applies in every organization of that app. Until that changes, check organization membership yourself (with the organization plugin's member roles) when a permission should only hold inside one organization.
</Callout>

## Creating a role with permissions

```go
import (
    "github.com/xraph/authsome/id"
    "github.com/xraph/authsome/rbac"
)

role := &rbac.Role{
    ID:    id.NewRoleID().String(),
    AppID: appID.String(),
    Name:  "Billing admin",
    Slug:  "billing-admin",
}
if err := eng.CreateRole(ctx, role); err != nil {
    return err
}

err := eng.AddPermission(ctx, appID, &rbac.Permission{
    ID:       id.NewPermissionID().String(),
    RoleID:   role.ID,
    Action:   "manage",
    Resource: "billing",
})
```

Role inheritance lives in Warden as a parent slug. `CreateRole` doesn't convert `ParentID` into one, so set up parent roles in Warden (its DSL or API) rather than through this field.

## Assigning and checking

```go
err := eng.AssignUserRole(ctx, appID, &rbac.UserRole{
    UserID: userID.String(),
    RoleID: role.ID,
})

allowed, err := eng.HasPermission(ctx, userID, "manage", "billing")
```

`eng.UnassignUserRole(ctx, appID, userID, roleID)` removes the assignment, and `eng.ListUserRoles(ctx, userID)` lists a user's roles.

## Guarding routes

```go
router.GET("/billing", billingHandler,
    forge.WithMiddleware(middleware.RequirePermission(eng, "manage", "billing")))
```

## HTTP API

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/roles` | Create a role |
| `GET` | `/v1/roles` | List roles |
| `GET`, `PATCH`, `DELETE` | `/v1/roles/:roleId` | Read, update or delete a role |
| `POST` | `/v1/roles/:roleId/permissions` | Add a permission |
| `GET` | `/v1/roles/:roleId/permissions` | List a role's permissions |
| `DELETE` | `/v1/roles/:roleId/permissions/:permissionId` | Remove a permission |
| `POST` | `/v1/roles/:roleId/assign` | Assign to a user (`user_id`; `org_id` is accepted but not applied) |
| `POST` | `/v1/roles/:roleId/unassign` | Remove from a user |

See [RBAC](/docs/security/rbac) for the default roles that `WithBootstrap` seeds.
