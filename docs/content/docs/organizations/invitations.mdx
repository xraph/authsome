title: Invitations

An invitation offers an email address a role in an organization. Whoever owns that address can accept it and becomes a member.

## The Invitation model

```go
import "github.com/xraph/authsome/organization"

type Invitation struct {
    ID        id.InvitationID  `json:"id"`     // ainv_ prefix
    OrgID     id.OrgID         `json:"org_id"`
    Email     string           `json:"email"`
    Role      MemberRole       `json:"role"`
    InviterID id.UserID        `json:"inviter_id"`
    Status    InvitationStatus `json:"status"` // pending, accepted, expired, declined
    Token     string           `json:"-"`
    TokenHash string           `json:"-"`
    ExpiresAt time.Time        `json:"expires_at"`
    CreatedAt time.Time        `json:"created_at"`
}
```

Invitations expire after `Config.InvitationTTL` (7 days by default; a negative value turns expiry off). Accepting an expired one returns `ErrInvitationExpired`.

## Delivering invitations

<Callout type="warn">
The plugin doesn't send invitation emails, and the token never appears in an HTTP response (`Token` is tagged `json:"-"`). An invitation created through `POST /v1/orgs/:orgId/invitations` can't reach the invitee unless you deliver the token some other way. To send invitations today, create them from Go, where you set the token, and email the link yourself.
</Callout>

```go
import (
    "github.com/xraph/authsome/account"
    "github.com/xraph/authsome/id"
    "github.com/xraph/authsome/organization"
)

token, err := account.GenerateVerificationToken()
if err != nil {
    return err
}

inv := &organization.Invitation{
    ID:        id.NewInvitationID(),
    OrgID:     orgID,
    Email:     "bob@example.com",
    Role:      organization.RoleMember,
    InviterID: inviterID,
    Status:    organization.InvitationPending,
    Token:     token,
}
if err := orgs.CreateInvitation(ctx, inv); err != nil {
    return err
}

sendInviteEmail(inv.Email, "https://myapp.com/invite?token="+token) // your code
```

## Accepting and declining

The invitee signs in and your frontend posts the token:

| Method | Path | Body |
|--------|------|------|
| `POST` | `/v1/orgs/invitations/accept` | `{"token": "..."}` |
| `POST` | `/v1/orgs/invitations/decline` | `{"token": "..."}` |

Accepting over HTTP only works for the user who owns the invited address (primary or a secondary email). Anyone else gets `ErrInvitationEmailMismatch` and the invitation stays pending. A new user signs up first, then accepts.

From Go, `orgs.AcceptInvitationAs(ctx, token, userID)` applies the same check, and `orgs.AcceptInvitation(ctx, token)` adds whichever account owns the address without checking who's asking, so call it only from trusted code. `orgs.DeclineInvitation(ctx, token)` declines.

## Listing

`GET /v1/orgs/:orgId/invitations` (admin or above) lists an organization's invitations, and `orgs.ListInvitations(ctx, orgID)` does the same from Go. There's no route or method to revoke one.
