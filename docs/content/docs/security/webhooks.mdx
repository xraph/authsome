---
title: Webhooks
description: Every webhook is a Relay delivery endpoint with a public URL, a once-shown rotatable secret, and Relay's signed deliveries.
---

Authsome does not deliver webhooks itself. A webhook you register with authsome is a delivery endpoint in [Relay](https://github.com/xraph/relay), the Forge event bus, and Relay does the delivering, retrying, and signing. Authsome owns the registration: it checks the URL, mints the secret, creates the Relay endpoint, and keeps a row that names it.

Without a Relay that can manage endpoints, the webhook routes answer `501 Not Implemented`. A webhook that cannot deliver is not registered at all, so you never hold a subscription that silently does nothing.

## The model

```go
import "github.com/xraph/authsome/webhook"

type Webhook struct {
    ID              id.WebhookID
    AppID           id.AppID
    EnvID           id.EnvironmentID
    URL             string
    Events          []string
    Secret          string // set on the way out of CreateWebhook and RotateWebhookSecret, never stored
    SecretHash      string // store.HashToken of the current secret
    RelayEndpointID string // the Relay endpoint that delivers for this webhook
    Active          bool
    CreatedAt       time.Time
    UpdatedAt       time.Time
}
```

The row holds a hash of the secret and the id of the Relay endpoint. Relay holds the secret, because Relay signs with it. Authsome shows it to you exactly once.

## Registering a webhook

`POST /v1/webhooks` with `{"url": "...", "events": ["user.created", "auth.*"]}` answers `201`:

```json
{
  "webhook": {"id": "awhk_...", "url": "https://api.example.com/authsome", "events": ["user.created", "auth.*"], "active": true},
  "secret": "whsec_..."
}
```

In Go:

```go
w := &webhook.Webhook{AppID: appID, URL: "https://api.example.com/authsome", Events: []string{"user.created", "auth.*"}, Active: true}
if err := engine.CreateWebhook(ctx, w); err != nil {
    return err
}
// w.Secret is the signing secret. This is the only time it is available.
```

<Callout type="warn">
The secret is returned once, in the create response, and never again. A later `GET` does not include it. If it is lost, rotate it.
</Callout>

Before the endpoint is created, authsome checks the URL and makes one test delivery to it:

- The URL must be `https`, name a host, and carry no credentials.
- Every address the host resolves to must be public. Loopback, private ranges, link-local addresses (the cloud metadata address among them), carrier-grade NAT, and the reserved blocks are refused. A name that answers with one public and one private address is refused.
- A `POST` with a `webhook.test` event, signed the way Relay will sign, must answer `2xx`. The client resolves the name itself, dials only addresses that pass the same check, and never follows a redirect: a `3xx` answer fails the check.

A refused URL answers `400`. The same checks run again when a webhook's URL changes.

For development against a receiver on your own machine, `Config.Webhooks.AllowInsecureURLs` permits `http` and non-public addresses. Never set it in production.

Event names are validated by shape (dotted lowercase words, `*` allowed as a segment) rather than against a fixed list, because plugins register their own event types with Relay at start.

## Managing webhooks

| Method | Path | What it does |
|--------|------|--------------|
| `POST` | `/v1/webhooks` | Register a webhook; answers the webhook and its secret |
| `GET` | `/v1/webhooks` | List an app's webhooks, without secrets |
| `GET` | `/v1/webhooks/:webhookId` | One webhook, without its secret |
| `PATCH` | `/v1/webhooks/:webhookId` | Change URL, events, or active state; mirrored to Relay |
| `DELETE` | `/v1/webhooks/:webhookId` | Remove the Relay endpoint, then the row |
| `POST` | `/v1/webhooks/:webhookId/rotate-secret` | Replace the secret; answers `{"secret": "..."}` once |

All routes require `manage` on `app`. The Go engine offers the same surface: `CreateWebhook`, `GetWebhook`, `ListWebhooks`, `UpdateWebhook`, `DeleteWebhook`, and `RotateWebhookSecret`.

Setting `active` to `false` disables the Relay endpoint: deliveries stop, and resume when it is set back.

Rotation takes effect at once. Relay signs the next delivery with the new secret, and the old one stops verifying. Update the receiver first, then rotate, or accept a brief window of rejected deliveries that Relay will retry.

## Verifying a delivery

Relay sends an HTTP `POST` with a JSON body and these headers:

| Header | Value |
|--------|-------|
| `X-Relay-Signature` | `v1=<hex>`, an HMAC-SHA256 over `<timestamp>.<raw body>` under the webhook secret |
| `X-Relay-Timestamp` | Unix seconds when the delivery was signed |
| `X-Relay-Event-Type` | The event name, such as `user.created` |
| `X-Relay-Event-ID` | The event's id |
| `X-Relay-Delivery-ID` | This delivery attempt's id |

Verify with the helper in the `webhook` package, which also refuses timestamps outside a five-minute window:

```go
import "github.com/xraph/authsome/webhook"

func handle(secret string) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        body, err := io.ReadAll(r.Body)
        if err != nil {
            http.Error(w, "cannot read body", http.StatusBadRequest)
            return
        }
        err = webhook.VerifyRelay(body, secret,
            r.Header.Get(webhook.RelayTimestampHeader),
            r.Header.Get(webhook.RelaySignatureHeader),
            0, // zero means webhook.DefaultSignatureTolerance
        )
        if err != nil {
            http.Error(w, "invalid signature", http.StatusUnauthorized)
            return
        }
        w.WriteHeader(http.StatusOK)
    }
}
```

`VerifyRelay` returns `ErrSignatureMismatch`, `ErrTimestampSkew`, or `ErrMalformedHeader`, all matchable with `errors.Is`.

The test delivery made at registration carries the same headers, signed with the secret you are about to be shown, and an `X-Relay-Event-Type` of `webhook.test`.

## Event types

The core engine registers these with Relay at start. Plugins register their own (the MFA, passkey, API key, consent, organization, waitlist, and subscription plugins among them), and a subscription may name any of them.

| Group | Events |
|-------|--------|
| user | `user.created`, `user.updated`, `user.deleted`, `user.email_verified`, `user.account_deleted` |
| session | `session.created`, `session.revoked` |
| auth | `auth.signin`, `auth.signin.failed`, `auth.signout`, `auth.forgot_password`, `auth.password_reset`, `auth.account_locked` |
| mfa | `auth.mfa.enabled`, `auth.mfa.enrolled`, `auth.mfa.verified`, `auth.mfa.challenged`, `auth.mfa.disabled` |
| passkey | `auth.passkey.registered`, `auth.passkey.authenticated`, `auth.passkey.deleted` |
| social and SSO | `auth.social.signin`, `auth.social.signup`, `auth.sso.signin`, `auth.sso.signup` |
| org | `org.created`, `org.updated`, `org.member.invited`, `org.member.joined`, `org.member.removed`, `org.member.role_changed` |
| environment | `environment.created`, `environment.updated`, `environment.deleted`, `environment.cloned` |
| device | `device.registered`, `device.trusted` |
| api key | `apikey.created`, `apikey.revoked` |
| consent | `consent.granted`, `consent.revoked` |
| admin | `admin.user.banned`, `admin.user.unbanned`, `admin.user.deleted`, `admin.sessions.bulk_revoked`, `admin.impersonate` |
| webhook | `webhook.created` |
| rbac | `rbac.role.created` |

Events are sent to Relay under the app id as the tenant, and an endpoint only ever receives its own app's events.

## Rows from before Relay

Webhook rows written by releases that delivered nothing are adopted the first time an engine with a Relay starts. Each gets a Relay endpoint of its own. A row that still holds its plaintext secret hands that same secret to Relay, so a receiver that already verifies with it keeps working and nothing has to be re-shared. A row with no secret gets a fresh one and starts disabled, since the secret has nowhere to be shown; rotate it, hand the new secret to the receiver, and enable the webhook. Adopted rows are rewritten with the hash and no plaintext.

Adoption does not re-check the URL. The rules above apply from the next change to it.

## Clones

Cloning an environment clones its webhooks as new Relay endpoints, each with a fresh secret and disabled, for the same reason: the clone has nowhere to show a secret. Rotate and enable each one you want live. A clone whose URL fails the checks, or a clone made without a Relay, is skipped with a warning rather than failing the whole clone.
