---
title: Account Lockout
description: Failed-attempt tracking that locks an account per client network, answers 423 with Retry-After, and clears on admin unlock.
---

Authsome counts failed password sign-ins and, after too many in a row, refuses further sign-ins for a while, whether or not the next password is right. Lockout is on by default and its state lives in the shared `authsome_kv` table, so it holds across every replica that shares the database.

## How it works

The counter is keyed by three things: the app, the identifier that was tried (email or username, lower-cased), and the client's network. IPv4 clients are grouped by /24 and IPv6 clients by /64. An attacker who fails five times from one network locks that network out of the account; the account's owner on another network still signs in. An operator who unlocks the account clears every network at once.

```
app:alice@example.com:203.0.113.0/24   attempts 1..5 -> locked for LockoutDuration
app:alice@example.com:198.51.100.0/24  untouched
```

The counter resets after `ResetAfter` without a new failure and on a successful sign-in from that network. A locked sign-in answers HTTP `423 Locked` with a `Retry-After` header and a body of the form:

```json
{"error": "account temporarily locked after too many failed attempts", "type": "account_locked", "retry_after": 874}
```

Lockout is one of two controls on repeated sign-ins. The other is rate limiting: every sign-in is also budgeted per client address and per identifier, and those refusals answer `429`. Lockout is the slower, longer control that survives an attacker rotating addresses inside one network.

## Configuration

Through the engine:

```go
cfg := authsome.DefaultConfig()
cfg.Lockout.MaxAttempts = 5
cfg.Lockout.LockoutDurationSeconds = 900
cfg.Lockout.ResetAfterSeconds = 3600

engine, err := authsome.NewEngine(authsome.WithConfig(cfg), /* store, warden, chronicle */)
```

Through the Forge extension's YAML:

```yaml
authsome:
  lockout:
    max_attempts: 5
    lockout_duration_seconds: 900
    reset_after_seconds: 3600
```

| Field | Default | Description |
|-------|---------|-------------|
| `Enabled` | `true` | Only an explicit `false` turns lockout off. |
| `MaxAttempts` | `5` | Failures from one network before that network is locked out of the account. |
| `LockoutDurationSeconds` | `900` | How long the lock lasts. |
| `ResetAfterSeconds` | `3600` | How long without a failure before the counter starts over. |

## The tracker

Lockout state goes through the `lockout.Tracker` interface:

```go
type Tracker interface {
    RecordFailure(ctx context.Context, key string) (attempts int, err error)
    IsLocked(ctx context.Context, key string) (locked bool, until time.Time, err error)
    Reset(ctx context.Context, key string) error
    ResetPrefix(ctx context.Context, prefix string) error
}
```

Two implementations ship:

- `lockout.NewKVTracker(kv, opts...)` keeps counters and locks in the store's `authsome_kv` table. The engine wires it by default, so nothing is needed for a deployment that shares a database.
- `lockout.NewMemoryTracker(opts...)` keeps them in the process. It is bounded and suited to development and tests. Pass it with `authsome.WithLockoutTracker` to replace the default.

A custom tracker takes the same option and must implement `ResetPrefix`, which clears every key that starts with `app:identifier:`; the KV tracker keeps a small index per prefix so it does not have to scan the store.

## Admin operations

Support staff unlock an account through the admin API:

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/v1/admin/users/{userId}/unlock` | Clears the lockout for the user on every client network. |

The route requires a session with `manage:user` and acts only on users in the caller's app; a user in another app reads as not found. From Go, the same operation is `engine.AdminUnlockUser(ctx, adminID, userID)`.

## Events on the trail

| Action | When |
|--------|------|
| `auth.signin` with outcome `failure` | A failed attempt was counted. The identifier is stored as a hash. |
| `auth.account_locked` | The network's counter reached `MaxAttempts`. |
| `auth.signin` with reason `account_locked` | A sign-in was refused because the lock was in force. |
| `admin.user.unlock` | An administrator cleared the lock. |
