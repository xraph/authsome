---
title: Audit Trail
description: Every security-relevant action is recorded on Chronicle, with request correlation, through one enriched path. Chronicle is required, nothing is recorded anywhere else, and the actions that matter most refuse to run when the trail is unavailable.
---

Authsome records every security-relevant action on [Chronicle](https://github.com/xraph/chronicle), the hash-chained audit trail used across the Forge ecosystem. There is no second store and no fallback logger: if Chronicle is not wired, the engine refuses to start. That is deliberate. An auditor cannot accept a deployment that might, under some configuration, have run with no record of who did what.

## Chronicle is required

When authsome runs as a Forge extension it looks for a `chronicle.Emitter` in the application container. The Chronicle extension provides one; without it, `Register` fails with:

```
authsome: the chronicle extension is required for the audit trail
```

When you build the engine yourself, pass a Chronicle through `WithChronicle`. `NewEngine` returns `ErrChronicleRequired` otherwise.

```go
import (
    "github.com/xraph/chronicle"
    chstore "github.com/xraph/chronicle/store"
    chpg "github.com/xraph/chronicle/store/postgres"

    authsome "github.com/xraph/authsome"
    "github.com/xraph/authsome/bridge/chronicleadapter"
)

trail, err := chronicle.New(chronicle.WithStore(chstore.NewAdapter(chpg.New(db))))
if err != nil {
    return err
}

engine, err := authsome.NewEngine(
    authsome.WithStore(store),
    authsome.WithChronicle(chronicleadapter.New(trail)),
    // ...
)
```

Tests use `bridge.NewMemoryChronicle()`, an in-memory recorder with `Events()` and `Reset()`.

## One path in

Every engine action emits a `hook.Event` on the engine's hook bus. The bus fills in what the call site did not: the timestamp, the outcome (derived from the error when one is set), the default severity, and the request correlation fields the auth middleware attached to the request. The first bus subscriber is the audit trail. Metrics and notifications subscribe after it, so they observe exactly the events the trail holds.

Plugins and middleware record through the same bus. Their audit helpers hold a `bridge.BusChronicle`, which turns a `bridge.AuditEvent` into a hook event and emits it, so a plugin cannot bypass enrichment or write to the sink directly.

## What every event carries

| Field | Meaning |
|-------|---------|
| `action` | The action name, dotted lower snake case, from the `hook.Action*` constants |
| `resource`, `resource_id` | What was acted on |
| `actor_id` | The user or principal that acted. Empty only for unauthenticated failures such as a wrong password |
| `tenant` | The app the action belongs to. Every event carries one; the bus logs a warning when a call site forgets |
| `org_id` | The organization, when the action is org-scoped |
| `outcome` | `success` or `failure` |
| `severity` | `info`, `warning` or `critical` |
| `category` | A grouping for reporting: `auth`, `admin`, `org`, `settings`, `oauth2`, `dashboard`, or a plugin name |
| `reason` | Why a failure happened, or a short human-readable cause |
| `ip`, `user_agent` | The client address (resolved through the trusted-proxy rules) and User-Agent. Chronicle seals both when crypto-erasure is on |
| `request_id` | Forge's request id, so one HTTP request can be reconstructed end to end |
| `session_id` | The authenticated session that performed the action |
| `metadata` | Action-specific detail |

## What is recorded

Authentication: sign-up, sign-in (once per session, whatever the method), sign-out, refresh and refresh-token replay, failed sign-in, account lockout, password change, password reset requested and completed, email verification requested and completed, MFA enrol, challenge, disable and recovery, passkey register, login and delete, social and SSO sign-in and sign-up, DPoP proof failures.

Sessions and principals: session create and revoke, machine authentication, delegation grant and revoke, impersonation start and stop.

Administration: user create, update, ban, unban, delete, copy and bulk import, bulk session revoke, app and environment lifecycle, role create, update, delete, assign and unassign, platform-owner grant, API key create and revoke, webhook create, update and delete.

Organizations: create, update, delete, member add, remove and role change, invitation accept and decline, team create, update and delete.

Settings: every set, enforce, unenforce and delete, with the key, scope, old value and new value.

Plugins: OAuth2 token exchange, SCIM provisioning, consent grant and revoke, risk assessments, anomaly and impossible-travel alerts, geofence, IP reputation and VPN blocks, new device detection, Shared Signals events.

## What is never recorded

The trail keeps evidence, not secrets or addresses:

- Password reset tokens and email OTP codes travel in `Event.Private`, which the notification handler reads and the audit subscriber drops. They never reach Chronicle.
- A failed sign-in stores `identifier_hash`, the SHA-256 of the lower-cased identifier, never the email or username.
- Admin actions on a user (ban, unban, delete, export, erasure) carry the user id, not the address or name.

## Actions that fail closed

Most events are recorded best-effort: a Chronicle outage is logged, counted and the request continues. A short list of actions is different, because they are irreversible or widen privilege, and an auditor will always ask for their record. These run `EmitCritical` before the action, and a refused record stops the action with an error:

- admin user delete
- impersonation start
- app delete
- organization delete
- platform-owner grant
- settings writes at global scope

## Querying

Chronicle owns the query surface. Use its admin API or the `audit.Query` type; `session_id` and `request_id` are indexed, so "everything this session did" and "everything this request did" are single queries. Chronicle's crypto-erasure removes the sealed personal fields for a subject while leaving the hash chain intact.

## Metrics

The engine's `MetricsCollector` receives `audit.record.failed` (a counter, labelled by tenant) whenever Chronicle refuses a record. Alert on it: a non-zero rate means the trail has gaps.
